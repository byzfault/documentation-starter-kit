## The Problem

Interface copy on an enterprise product comes from many hands and is reviewed screen by screen against written standards. A reviewer applies the same dozens of rules by hand, every release. Some rules are mechanical, such as casing and label wording. Others need judgment, such as tone in an error message and whether the copy fits the task.

The question is how to hand part of that review to an AI agent without producing a confident tool that flags the wrong things at scale.

## The Approach

**Split the rules by how they can be applied.** I started from an existing content audit and sorted every rule it implied:

| Kind | Examples | How it runs |
|---|---|---|
| Deterministic | Casing, punctuation, label wording, term swaps | Small single-purpose checks. One rule per skill, pass or fail |
| Judgment | Tone, empathy in errors, task fit | A short core guideline the model loads as context |

**One rule per skill.** If a skill needs the word "and", it becomes two. Each skill has one trigger, one outcome, before and after examples and a stated exception. A reviewer can say pass or fail without opinion.

**One guideline for the rest.** Tone and apologetic language depend on the situation: whose fault the failure is, how risky the action is. Cutting that into separate skills would let each one optimise its own rule and undo the others, so it stays in one place with principles, examples and a rule for resolving conflicts.

**Deterministic first, model second.** Anything a rule can check goes to a check that never drifts. The model is used only where judgment is needed.

**Every conflict goes on a register.** Where two standards disagree, the question has an owner and a status. It does not get decided inside a prompt.

## Platform Limits Shape the Design

The delivery platforms set the boundaries: how many skills a request can invoke, what an agent can read on the canvas and what it can change. I treat those as test questions to answer early, not assumptions. The rules are written once as plain Markdown so they can be wrapped for Figma and Copilot without being rewritten.

## How I Plan to Evaluate It

- **Real scenarios.** Real screens from a release, not invented examples
- **Rule-level scoring.** For each rule: how often it fires correctly, how often it fires wrongly and what it misses
- **False-positive control.** An agent that flags the wrong things is worse than none, so the quality bar is set before the rollout
- **Human preference on tone.** Reviewers compare agent suggestions with their own edits
- **A baseline.** The same screens reviewed by hand, to see whether the agent saves time without lowering quality

## Why It Matters

This is solution design applied to content. The decisions are the same as in any architecture review: where deterministic code ends and a model begins, what the failure modes are, how it is tested and who owns each rule.
